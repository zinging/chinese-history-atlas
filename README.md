学历史最常见的挫败是：年代表背了又忘，皇帝、思想家、诗人、工匠各记各的，脑子里始终是一堆散点。

这个站想解决的就是这件事。**同一个时代，皇帝在朝堂上做了什么决策、思想家在书斋里如何回应、诗人在流放路上写下了什么、工匠在工坊里又造出了什么 —— 四条线并排展开。** 你看到的不再是孤立的人名和年份，而是一个时代的因果和全貌。



* 想系统梳理朝代脉络的历史爱好者，能在这里立起时间坐标；

* 想入门传统文化的人，能沿着儒释道看清思想怎么流变；

* 学生则可以从「背年代」转向「理解因果」；

* 对科技史感兴趣的人，能从《考工记》一路读到《天工开物》《本草纲目》。

## 🗺️ 四大板块 —— 帝王谱系、思想源流、诗词鉴赏、格物致知

### 🏮 帝王谱系

从隋到清七朝 **77 位皇帝**，一条横向卡片流贯穿。点开即见生平时间线、人物关系图、冷知识与争议话题；地图叠加各朝疆域轮廓、古地名点与行军航海路线动画。悬案疑案逐案拆解 —— 从「名称怎么来的」到「到底谁该负责」，再到开放讨论；探案问史则把带出处的线索交给你，由你自己下判断。



![帝王谱系](docs/demo/module-emperors.gif)

### 📚 思想源流

儒（孔孟）、道（老庄）、佛（禅宗）、诸子（兵法 / 法家 / 墨家）、理学心学（朱熹 / 王阳明）—— 中国人的底层操作系统，从先秦一路延续到明清。每个流派精选核心经典，**结合作者当时的处境读原文**，而非脱离时代死记；再以辩证选择题训练思辨，一道题同时考「怎么评价」与「因果链是什么」。



![思想源流](docs/demo/module-thought.gif)

### 🎋 诗词鉴赏

从屈原到纳兰性德，按朝代编排 **22 位文人**。这里不做机械背诵 ——**先看诗人一生的行迹地图，再读一首诗背后的处境、心情与公案**。李白为何在江陵写下「轻舟已过万重山」？因为他刚接到大赦令，劫后余生，船才显得那么快。诗路舆图标出他们去过哪里、又在哪里写下名句。



![诗词鉴赏](docs/demo/module-poetry.gif)

### 🧭 格物致知

18 部古代科技典籍 —— 工艺营造（考工记 / 营造法式 / 天工开物 / 梦溪笔谈）、医药本草（黄帝内经 / 伤寒论 / 千金要方 / 本草纲目）、农书（齐民要术 / 农政全书）、算历（九章算术 / 周髀算经 / 授时历）、地理博物（山海经 / 水经注 / 徐霞客游记）、生活艺术（茶经 / 园冶）。**器物图谱**按书分组展示 48 件代表性器物，配博物图谱风格工笔白描插图；**工艺公案**追问「活字印刷为什么没普及」「李时珍为什么花 27 年重编本草」；**格物问典**给出带史料线索的思辨题，由你自己判断。

![格物致知](docs/demo/module-gewu.gif)

## ✨ 这个项目有什么不同

**🗡️ 四条线并行，而不是四个孤立页面**

皇帝的决策、思想家的回应、诗人在流放路上的句子、工匠在工坊里的发明，本就是同一个时代的四个侧面。传统历史站只讲帝王，这里让你看见权力、思想、审美与工艺如何彼此牵动。

**🗺️ 历史落在地图上，而不是文字里**

可缩放 Leaflet 底图叠加疆域轮廓与古地名，靖难南下、郑和七下西洋、清军入关都按时间分段动画呈现，而非一张静态图；点任意古地名即可对照今址（如「睦州」≈ 今浙江建德一带）。

**📂 案件式深读，而不是百科式罗列**

著名疑案拆为八段：名称由来 → 背景 → 人物 → 经过 → 结果 → 影响 → 开放讨论 → 史料出处。给你的是完整推理链，而不是「某某年发生某事」的一句话。

**📝 132 道辩证题，而不是是非题**

全站 132 道选择题：帝王谱系 77 道（每位皇帝一道）+ 思想源流与诗词鉴赏 41 道 + 格物致知 14 道。分两类 ——**论证判断**（「你如何评价这项政策？」）与**因果链**（「此事因何发生？直接原因是什么？」）。提交即批改并附解析，部分为开放题，可选接 AI 老师点评。

**🔍 线索可溯源，演义与正史分开**

时间线与侦探线索均标注《旧唐书》《宋史》《明史》等出处；演义传说单独标注「小说演绎，正史不载」，不让你把《三国演义》当正史读。

**🖼️ 器物图谱，而不是空泛介绍**

48 件古代器物 —— 从后母戊鼎、错金银铜方案，到景德镇青花瓷、风炉二十四器 —— 每件配博物图谱风格工笔白描插图，按书分组，点开可放大看细节。

**⚡ 零依赖，打开即用**

纯原生 HTML / CSS / JS，无构建、无框架、无后端；`data/` 全是可读可改的 JSON，无需 `npm install`，也无需数据库。

**🤖 可接 AI 私教，数据不出本机**

内置 OpenAI 兼容接口（DeepSeek / OpenAI 等），配置仅存于本机 `web/llm-config.json`（已 gitignore），问答内容不上传任何服务器。

## 🚀 快速开始

环境要求：**Node.js 18+**（自带 `fetch`，无需 `npm install`）。



```
git clone git@gitee.com:chen_ye_code/chinese-history-atlas.git
cd chinese-history-atlas
node web/serve.mjs
# 然后浏览器打开 http://127.0.0.1:5173/web/
```

💡 **端口被占用**：运行 `node web/serve.mjs 8080` 即可换端口。

⚠️ **请用本地服务器打开，不要直接双击 HTML**：前端通过 `fetch` 读取 `data/*.json`，`file://` 方式会被浏览器 CORS 拦截，导致页面空白。

**可选・接入 AI 老师**：在探案问史页底部打开「🤖 AI 老师配置」，填入 OpenAI 兼容接口、Key 与模型（点 ⬇ 可自动拉取模型列表）。配置仅存于本机 `web/llm-config.json`（已 gitignore）；仓库附带带注释的 `web/llm-config.json.template`，复制改名为 `llm-config.json` 后即可填写。

## 📖 内容规范



* **史实优先**：只讲有史料依据的内容；存疑处明说「没有确切记载」；演义传说标注「小说演绎，正史不载」。

* **通俗表达**：短句口语，专有名词首现时括号解释（如「幽云十六州（今北京、天津及山西、河北北部一带）」）。

* **学习者为主导**：开放问题不设标准答案，先留思考空间再补史实；选择题正确项打散位置，避免靠位置猜答。

* **中立立场**：不站队、不美化，争议话题呈现多方观点后交由学习者自行判断。
