### 周用「单目录 + 双世系」，不拆成两个目录

现有 `DYNASTY_SEGS`（西汉/新莽/东汉三段）是**只服务 han 一个朝代的特例**，拆周会变成第二套特例，代价是两套目录、两套地图、两套文案。而 `jin`（两晋 15 帝）已经跑通了**单目录 + `meta.lineages: {jinwest, jineast}`** 的机制：时间线自动立「西晋 / 东晋」两块段牌，地图仍是一张，文案一段。周照抄这条路径，改动量最小。

- `data/zhou/emperors/index.json` 的 `meta.lineages` 写 `{"zhouwest":"西周","zhoueast":"东周"}`；
- 22 位帝王每人都带 `lineage`，值与索引严格一致（校验器强制）。

## 8. 校验规则：必须按现状对齐的三条硬约束

**1）`reign` 一律对象 + 带负号的字符串**（`scripts/validate.mjs` 109–121 行）：字符串形式的 `reign` 只认 `^(\d{4})-(\d{4})$`（4 位正整数），负号会直接报错。所以：

```json
"reign": { "start": "-2070", "end": "-2050" }
```

值必须是**字符串**（带负号），不是 number；`emperors/index.json` 与每位帝王 json 里的 `reign` 必须逐字一致。字符串式 `"-2070--1600"` 只出现在 `DYNASTY_RANGE` 这类展示字段里。

**2）`lineage` 一致性**（131–143 行）：`meta.lineages` 一旦登记，**每位帝王必须带 `lineage` 且与 index 一致**；未登记的朝代**不得出现** `lineage` 字段。→ 周必须登记 `{zhouwest, zhoueast}` 且 22 帝全带；夏、商一个都不能带。

**3）id 与引用**：

- 帝王 `^<key>-emp-[a-z0-9]+$`（`xia-emp-yu` / `shang-emp-tang` / `zhou-emp-wuwang`）；
- 事件 `<key>-event-*`、人物 `<key>-p-*`（注意是新版前缀 `xia-p-boyi`，旧版 `xia-person-*` 亦可但两朝统一用 `-p-`）、案件 `<key>-case-*`、路线 `<key>-yuji` 式自由命名；
- `timeline` 按 `date` 升序，日期形如 `-2070` 或 `-2070-07`；
- `cases.json` 的 `categories` 只登记本朝实际用到的键（夏/商：`court / thought`；周：加 `war`）；
- 交叉引用（帝王 `majorEvents` / `people` 是否登记在事件库/人物库）只出 warn，但**人物画像缺失是硬指标**：凡进关系图的人名必须有像。

## 10. 风险与已知敏感点

1. **朝代条**：12→15 按钮。机制是横滑，不会撑破；但移动端 390 只露 2 个按钮，翻页次数 +1，需重看箭头提示与初始滚动位置（这块前四轮改过箭头，用户极敏感）。
2. **「全部」视图**：帝数 133→177，卡片墙变长，需确认首屏性能与滚动体验。
3. **公元前纪年**：所有 `reign` 必须对象式负数；时间线排序、跨公元前后的显示要抽查（周不跨，夏商全在公元前，风险低）。
4. **夏是否信史**：全站口径建议写明「夏代以二里头等考古发现与《史记·夏本纪》《竹书纪年》互证，学界对具体王世与年代仍有争议」，帝王卡片同样标注「推定」，**不写成确定纪年**。
5. **关系图缺图**：人名与画像一一对应是硬指标，58 人物里凡入关系图的都必须有像（当前计划 100% 覆盖，无占位）。
6. **制度板块**：`institutions` 目前**只在明朝加载**（`app.js` 第 387 行 `dyn === 'ming' ?`）。夏商周若要有制度 tab，需要额外改造加载逻辑 + 新数据，本期**建议不做**（各朝 tab 保持一致即可）。
7. **gantt**：现有 `gantt.json` 只有三国/两晋/五代。东周列国并立其实很适合做甘特图，但属增量功能，**本期不做**。
